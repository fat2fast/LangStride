# Content Contribution

> **Languages**: English | [Tiếng Việt](../../vi/fr/content-contribution.md)

- **Status**: In Specification
- **Last Updated**: 2026-09-25
- **Scope**: Public MVP (P1–P5)
- **Authority**: Functional Requirement Specification (Canonical)

### FR-CONT-001 — Lesson contribution
A contributor shall add or edit lesson content through repository files. Done when a documented pull-request workflow accepts a lesson content change.

### FR-CONT-002 — Roadmap contribution
A contributor shall propose roadmap changes. Done when roadmap data changes can be proposed and reviewed through Git.

### FR-CONT-003 — Practice contribution
A contributor shall add a practice challenge. Done when a valid challenge file can be added through the documented workflow.

### FR-CONT-004 — Debug/review contribution
A contributor shall add a debug or review challenge. Done when static P4 exercise content can be added through the documented workflow.

### FR-CONT-005 — Content schema documentation
The repository shall document the content schema. Done when a contributor can determine required and optional lesson/concept fields before submitting a change.

### FR-CONT-006 — Challenge schema documentation
The repository shall document the challenge schema. Done when a contributor can determine fields and deterministic validation data for every supported challenge type.

### FR-CONT-007 — Content structure validation
CI should validate contributed content structure. Done when an invalid contribution is rejected by the contribution validation path.

### FR-CONT-008 — Source metadata
Technical content should include authoritative source metadata. Done when contributors can attach sources and reviewers can inspect them in the proposed content.
